# 评测脚本归档区

这里保存意图路由评测过程中的**一次性诊断脚本**。它们记录了 2026-08 下旬
"路由之战"的完整调试轨迹，保留下来是为了让度量演化过程可回溯。

## 演化脉络（对应当时的探索过程）

1. **`intent_probe_retry.py`** —— 初版全量探针（68 场景）发现意图路由
   准确率不理想后，第一轮补救：对失败用例带上下文重试，试图区分
   "路由真的错"和"单次调用抖动"。
2. **`intent_rejudge.py`** —— 重试后发现判定口径本身有问题（路由对但
   内容不达标也算 PASS？），于是把判定拆开：路由正确性（确定性比对）
   与意图达成度（LLM 评审）分别重新判分。
3. **`intent_final_tally.py`** —— 聚合多轮结果，按意图类别统计最终
   准确率与错例分布，产出第一份可对外的准确率数字。

## 结论沉淀

这三轮脚本的经验最终固化进了正式探针 `scripts/intent_probe.py`：

- 判定口径统一为"路由正确 + 关键内容存在 + 无禁止内容 + LLM 评审意图达成"
- 增加 LLM 预检 fail-fast（避免配额中途死亡跑出无效基线）
- 增加 429 退避与限流冷却（避免探针自身触发限流污染结果）
- 场景扩充至 88 条、7 个阶段

这些脚本**不再维护**，仅供回溯当时的问题定位过程。当前评测入口是
`scripts/intent_probe.py`，报告聚合见 `scripts/eval_report.py`。
